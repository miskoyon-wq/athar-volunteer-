💡 لماذا GitHub Pages؟ مجاني تمامًا، سرعته عالية، ولا يحتاج أي سيرفر أو صيانة. وهو نفس الرابط الذي ستستخدمه كـ Privacy Policy URL في Google Play.
🚨 اقرأ هذا أولاً — أكثر سببين يمنعان الموقع من العمل:
  1. المستودع Private: GitHub Pages المجاني يعمل مع المستودعات العامة Public فقط. لو مستودعك خاص سيعطي الرابط 404 دائماً — حتى لو كل شيء آخر صحيح.
  2. اسم المستودع في الرابط غير مطابق: لازم تكتب الاسم حرفياً كما هو في GitHub (انتبه للشرطات - في آخر الاسم).

الحل بالتفصيل في القسم «حلّ المشاكل» أسفل هذا الدليل.

٤ رفع الملفات (الطريقة الأسهل)

١.٤ في صفحة المستودع الجديد

ستجد رابط في المنتصف اسمه uploading an existing file — اضغط عليه.
(أو من القائمة العلوية: Add file ← Upload files)

٢.٤ اسحب الملفات

افتح مجلد الملفات المفكوكة، ثم:

  1. حدّد كل الملفات والمجلدات من داخل المجلد (اضغط Ctrl+A).
  2. اسحبها وأفلتها في المستطيل الكبير في الصفحة.
  3. انتظر حتى تظهر كل الملفات في القائمة (قد يأخذ دقيقة — الحجم ~14 ميجا).
٣.٤ أكمل العملية

في خانة الوصف أسفل الصفحة اكتب: Athar site

ثم اضغط الزر الأخضر Commit changes.

🚨 تحقق من ملف .nojekyll: بعض المتصفحات لا ترفع الملفات التي تبدأ بنقطة عبر السحب. بعد الـCommit، تأكد أن .nojekyll ظاهر في قائمة الملفات.

إن لم يظهر: اضغط Add file ← Create new file، واكتب في خانة الاسم بالضبط: .nojekyll (اترك محتواه فارغًا تمامًا)، ثم اضغط Commit. بدون هذا الملف لن يعمل الموقع بشكل صحيح.

٦ رفع ملف التطبيق (APK)

ليش خطوة منفصلة؟ GitHub لا يقبل رفع ملف واحد أكبر من 25 ميجابايت من المتصفح، وملف التطبيق حجمه 52.7 ميجابايت. الحل: نرفعه في قسم Releases (وهو مسموح حتى 2 جيجابايت).
١.٦ اذهب إلى Releases

من الصفحة الرئيسية للمستودع، في الشريط الجانبي الأيمن اضغط Releases.
ثم اضغط Draft a new release (أو Create a new release).

٢.٦ اكتب وسم الإصدار

في خانة Choose a tag اكتب بالضبط: v1.3.0 ثم اضغط Create new tag.

٣.٦ اكتب العنوان وأرفق الملف

Release title: أثر — الإصدار 1.3.0

ثم في قسم Attach binaries اسحب ملف athar-1.3.0.apk وأفلته، وانتظر حتى ينتهي الرفع (شريط تقدّم).

٤.٦ انشر الإصدار

اضغط Publish release. هكذا أصبح رابط التحميل المباشر:

https://github.com/USERNAME/athar-site/releases/download/v1.3.0/athar-1.3.0.apk
✅ صفحة التحميل تتكيّف تلقائيًا: صفحة /download/ عندنا ذكية — بتجرّب الملف المحلي أولاً، وإذا ما لقيته بتحوّل تلقائيًا لرابط الإصدارات أعلاه. فبس تأكد أن اسم الحساب في الرابط يطابق حسابك.

٧ هل يهم اسم المستودع؟

لا، لا يهم إطلاقًا. الحزمة مبنية لتعمل تحت أي اسم وأي نطاق:
  • كل الروابط داخل الموقع نسبية (app/ · download/ · ../assets/) — تعمل تحت أي مسار.
  • زر تحميل التطبيق يستنتج رابط الإصدارات تلقائيًا من رابط الصفحة نفسها.
مثال: لو اسم المستودع athar-volunteer- فالرابط https://USERNAME.github.io/athar-volunteer-/ ويعمل مباشرة.

الاستثناء الوحيد: لو سمّيت المستودع بنفس اسم حسابك + .github.io. في هذه الحالة، اكتب الرابط يدويًا في المتغيّر APK_URL_OVERRIDE داخل download/index.html.

٩ الطريقة الاحترافية (اختياري — أمر واحد)

لو عندك git مثبّت على جهازك، تقدر تنشر كل شيء بأمر واحد من داخل المجلد المفكوك:

bash deploy.sh USERNAME

استبدل USERNAME باسم حسابك. السكربت تلقائيًا: يهيّئ git، يعمل Commit، ويرفع كل الملفات.
(سيُطلب منك اسم المستخدم وكلمة مرور — استخدم Personal Access Token بدل كلمة المرور.)

كيف تعمل Personal Access Token؟ GitHub ← صورتك ← Settings ← Developer settings ← Personal access tokens ← Tokens (classic) ← Generate new token ← اختر صلاحية repo ← انسخ الرمز والصقه مكان كلمة المرور.
